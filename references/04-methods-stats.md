# Phase 4: methods, statistical rigor, and every reported number

Goal: the design can support the claims, the statistics are appropriate and fully reported, and every
number in prose, tables and figures is internally consistent and, where the paper gives enough information,
reproducible. Every number you call consistent or inconsistent must have been computed by code in this
session: an item without a `command` is counted as not checked. Recompute with `scripts/recompute_metrics.py`; never estimate arithmetic by eye, and paste the
command and its output into the finding's `evidence` (`kind: computation`).

## Contents
- A. Read the design
- B. Methods validity
- C. Statistical rigor (failure modes)
- D. Number reconstruction
- E. Machine-learning and prediction papers

## A. Read the design first

Write down, before judging anything: the research question; units of analysis and what `n` counts; groups,
conditions and comparators; how data were collected, labeled, split, and excluded; the outcome measures;
the analyses linked to each main claim. If any of these cannot be found, that absence is itself a finding.

## B. Methods validity

- Does the design answer the question asked? Is the comparator fair (same data, same tuning budget)?
- Is the independent unit right? Cells, images, repeated readings, posts from one user, articles about
  one event, or several model runs are not independent samples. Pseudo-replication is a critical finding
  when it drives a significance claim.
- Leakage: test data used in tuning, preprocessing fit on all data, duplicates or near-duplicates across
  splits, the same event or entity on both sides of a split, labels generated by a model related to the one
  evaluated, features that encode the outcome.
- Label quality: who or what produced the ground truth, agreement statistics (kappa, alpha) with the
  sample they were computed on, and whether evaluation uses the same labels as training.
- Selection and exclusion: stated before analysis? numbers removed at each step? effect on results?
- Confounding and causal language: association written as cause, mediation, or mechanism without a design
  that supports it.
- Reproducibility: software and versions, seeds, hyperparameters, hardware, code and data availability.

## C. Statistical rigor: failure modes to look for

Critical or major (affects inference):
- Wrong unit of analysis / pseudo-replication; nested data analyzed as independent.
- Many comparisons with no correction and no pre-specification; selective reporting of the significant ones.
- A test that does not fit the data (paired data with unpaired test, parametric test on tiny skewed
  samples with no rationale, chi-square with expected counts under 5).
- Interaction claimed from two separate tests ("significant in A, not in B" does not show A differs from B).
- Significance used as the only evidence; no effect size or uncertainty for a main result.
- Overclaiming from small samples; "no difference" concluded from a non-significant test (absence of
  evidence) without an equivalence analysis or a power statement.
- Post-hoc outlier removal without a rule; changing the analysis after seeing results.
- Regression or correlation written as prediction or mechanism without validation or design support.
- Confidence interval used where a prediction interval is meant (per-observation uncertainty).

Reporting (major or minor):
- Error bars or "±" not defined (s.d., s.e.m., CI); `n` not stated per panel or per group.
- Exact p values missing where thresholds or stars are used; stars not defined; "ns" hiding the value.
- Test statistic and degrees of freedom missing for main tests; one- vs two-sided not stated.
- Software and version not given.

## D. Number reconstruction (do every one the paper makes possible)

| Paper gives | Recompute | Command |
|---|---|---|
| Confusion matrix | accuracy, per-class precision/recall/F1/specificity, macro/weighted F1, balanced accuracy, kappa, MCC; compare with every reported value | `cm --matrix '[[...]]' --labels a,b --reported '{...}'` |
| Counts and totals | percentages at the reported precision; do the parts add up to the total | `pct`, `sum` |
| Test statistic + df | p value; does it match the reported p and stars | `pvalue --test t --stat --df` |
| Proportion with CI | Wilson / Clopper-Pearson interval; which method the paper used | `ci --k --n` |
| Mean of integer data + n | GRIM consistency | `grim --mean --n [--items]` |
| Split sizes | train/val/test sum to the total; class supports in tables sum to the test size | `sum` |
| Table rows/columns | totals, row percentages, ranking statements, "best" bolding matches the max | by hand with `sum`/`pct` |
| Figure values | numbers in captions and prose match the table or the plotted data (read values off the image only for gross mismatches, and say so) | |
| Raw data or code supplied | rerun the analysis or the metric computation in a scratch folder; never inside the user's project | Python in the venv |

Also check: rounding consistent with the reported precision; the same metric to the same decimals
everywhere; differences between models computed from the reported values (e.g. "outperforms by 0.0644"
equals the difference of the two table values); per-class supports match the class distribution and split.

A mismatch beyond rounding is critical when it concerns a headline result, major otherwise. State both
values and the computation.

## E. Machine-learning, NLP and prediction papers

- Baselines: strong and current, tuned with comparable effort; a majority-class and a simple baseline.
- Variance: more than one seed or fold, with spread reported; differences smaller than the spread are not
  improvements. Significance tests or bootstrap CIs for headline comparisons.
- Class imbalance: macro metrics and per-class results; thresholds chosen on validation data only.
- Splits: stratified/temporal/grouped as the claim requires; grouping by source, event, user or document
  when items are related.
- LLM-generated labels or LLM-as-judge: validation against human labels on a held-out sample, agreement
  reported, prompts and model versions given, and the risk that the evaluated model shares biases with the
  labeler.
- Calibration and error analysis for anything framed as deployable.
